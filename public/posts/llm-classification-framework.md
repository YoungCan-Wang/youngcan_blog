# 深入剖析大模型分类体系与推理模型本质

你真正要理解的是：**GPT、Gemini、Claude、DeepSeek 这些名字不是一种分类方式。真正的底层分类是：Base Model、Chat/Instruct Model、Reasoning Model、MoE Model、Long-context Model、Multimodal Model、Agentic Model。**

“推理模型”和“非推理模型”不是两个物种。它们底层大多还是 Transformer，自回归生成 token。区别主要在 **训练目标、后训练方式、推理时计算预算、是否显式/隐式产生中间思考步骤**。

---

## 一、所有大模型的共同底层：下一个 token 预测

大语言模型最底层做的事很朴素：给它一串文本，它预测下一个 token。

比如输入：

> “北京是中国的”

模型会根据参数里的统计和语义结构，预测下一个 token 大概率是“首都”。

它不是数据库检索，也不是人脑思考。它本质是一个巨大的函数：

$$\text{输入上下文} \rightarrow \text{神经网络前向计算} \rightarrow \text{输出下一个 token 的概率分布}$$

然后不断重复：

$$\text{第 1 个 token} \rightarrow \text{第 2 个 token} \rightarrow \text{第 3 个 token} \rightarrow \text{最终答案}$$

所以模型回答一段话，本质上是连续很多次“预测下一个 token”。

区别在于：模型在预训练中吸收了大量文本、代码、数学、对话、网页、论文、书籍、问答、工具调用轨迹，所以它的“下一个 token 预测”已经隐含了语言、知识、逻辑、代码结构、世界规律。

> [!IMPORTANT]
> **LLM 的第一性原理**：它是压缩在参数里的概率世界模型。

---

## 二、Base Model、Instruct Model、Chat Model、Reasoning Model 的区别

这几个概念必须分清。

*   **Base Model** 是原始基础模型。它只学“续写文本”。你问它问题，它不一定会老实回答，它可能继续模仿网页、论文、论坛、小说。它没有天然的“助手人格”。
*   **Instruct Model / Chat Model** 是经过指令微调和人类偏好训练后的模型。它学会了“听指令、回答问题、拒绝危险请求、按格式输出、像助手一样说话”。
*   **Reasoning Model** 是进一步强化“先分析、再回答”的模型。它通常会在最终答案前生成一段显式或隐式的中间推理过程，也就是所谓 chain-of-thought / thinking tokens。[DeepSeek 官方](https://api-docs.deepseek.com/guides/reasoning_model)对 `deepseek-reasoner` 的描述就是：模型在给出最终答案前先生成 CoT 来提高回答准确性。[OpenAI](https://openai.com/index/learning-to-reason-with-llms/) 也公开讲过，推理模型的表现会随着训练时强化学习规模和推理时思考时间增加而提升，这就是所谓 test-time compute。

> [!TIP]
> **一句话总结**：Base Model 学续写。Chat Model 学对话。Reasoning Model 学会在回答前多花计算量做中间推演。

## 三、推理模型 vs 非推理模型的核心区别

非推理模型更像“快速反应系统”。你问：“帮我把这段话润色一下。”它不需要拆解问题，不需要证明，不需要反复检查。它直接根据语言模式输出结果。

推理模型更像“慢速演算系统”。你问：“这个复杂系统设计哪里会有一致性问题？”或“这个股票策略为什么回测好、实盘差？”它会先做多步拆解：识别条件、建立中间状态、尝试路径、检查矛盾、修正答案，再输出最终结论。

### 底层差别对照表：

| 维度 | 非推理模型 | 推理模型 |
| :--- | :--- | :--- |
| **生成方式** | 直接生成答案 | 先生成中间思考，再生成答案 |
| **计算量** | 少 | 多 |
| **延迟** | 低 | 高 |
| **成本** | 低 | 高 |
| **擅长** | 摘要、翻译、改写、分类、简单问答、常规代码 | 数学、复杂代码、规划、多约束决策、debug、推演 |
| **风险** | 容易浅层回答 | 可能过度思考、绕远、把简单问题复杂化 |
| **本质** | 快速模式匹配 + 语义生成 | 模式匹配 + 多步搜索/验证式生成 |

> [!WARNING]
> **注意一个关键点**：推理模型不等于真正会逻辑证明。它不是 Prolog，不是 SAT Solver，不是形式化证明器。它还是概率模型。它只是被训练成更擅长生成“看起来像有效推理、并且在很多任务上确实更有效”的中间步骤。

所以推理能力来源不是“拥有理性灵魂”，而是：
1. 训练数据里有大量解题过程；
2. 后训练奖励它多步解决问题；
3. 推理时给它更多 token 预算；
4. 模型可以在中间步骤中自我修正；
5. 对数学、代码、逻辑题，用结果正确性做强化学习。

[DeepSeek-R1 的论文](https://arxiv.org/abs/2501.12948)就很典型：它强调通过强化学习激励模型产生推理能力，并出现 self-reflection、verification、dynamic strategy adaptation 这类行为。

## 四、为什么“多想一会儿”真的会变强

普通模型回答问题像这样：
$$\text{输入问题} \rightarrow \text{直接输出答案}$$

推理模型回答问题更像这样：
$$\text{输入问题} \rightarrow \text{拆问题} \rightarrow \text{生成候选路径} \rightarrow \text{检查条件} \rightarrow \text{修正错误} \rightarrow \text{输出答案}$$

这中间多出来的 token，就是 reasoning tokens / thinking tokens。这些 token 不一定展示给用户。有些模型隐藏，有些模型可以部分展示，有些模型只给最终答案。

> [!NOTE]
> 推理模型变强的原因很简单：**中间 token 给了模型一个临时工作区（工作记忆）**。

例如让模型算：“一个商品先涨价 20%，再降价 20%，最后价格变了吗？”
*   **非推理模型**：可能直接套话说“回到原价”。
*   **推理模型**：会写中间过程：
    1. 原价 100
    2. 涨 20% $\rightarrow$ 120
    3. 降 20% $\rightarrow$ 96
    4. 所以不是原价，而是少了 4%

这个中间过程就是外部化的工作记忆。更复杂的代码、数学、规划任务也是一样。如果不给它中间状态，它容易“凭感觉生成”。

## 五、推理模型的训练方式：SFT、RLHF、RLVR、Distillation

大模型通常分五层训练路线：

1.  **Pretraining**：用海量文本和代码训练下一个 token 预测。学知识、语言、代码和世界模型。
2.  **SFT (Supervised Fine-Tuning)**：人工或模型生成高质量问答，让模型学会按照指令回答。
3.  **Preference Training / RLHF / RLAIF**：人类或 AI 对多个答案排序，模型学习“哪个答案更好”，让模型更像助手、更安全。
4.  **RLVR (Reinforcement Learning with Verifiable Rewards)**：对推理模型很关键。数学题、代码题、选择题都有明确对错。模型可以不断尝试，答对给奖励，答错不给奖励。久而久之，它会学出更强的分解、验证、反思能力。
5.  **Distillation (蒸馏)**：用强推理模型生成大量推理数据，再训练小模型模仿它。[DeepSeek-R1](https://huggingface.co/deepseek-ai/DeepSeek-R1) 开源时就包含蒸馏模型，这是推理能力下放到小模型的重要路径。

## 六、Pro、Flash、Sonnet、Opus、R1 这些名字背后分别是什么维度

这些名字属于不同的分类维度，不要混在一起看。

*   **Pro / Opus**：通常表示**高能力档**。参数量、训练量、推理预算、复杂任务表现更强，但更慢、更贵。
*   **Flash / Mini / Haiku**：通常表示**速度档**。延迟低、成本低、吞吐高，适合高频线上业务，但复杂推理弱一些。
*   **Sonnet**：通常表示**平衡档**。不是最贵最强，但速度、成本、智能程度比较均衡。
*   **R1 / o 系列 / reasoning 线**：表示**推理优化档**。重点不一定是聊天最自然，而是数学、代码、复杂决策、多步推演更强。
*   **V3 / V4 / GPT-5.5 / Gemini 3.x**：更像**代际版本号**。说明是某一代基础能力，但不直接说明它是不是推理模型。

### 正确的模型认知脑图：

*   **能力档**：`Flash` < `Standard/Sonnet` < `Pro/Opus`
*   **推理档**：`普通 Chat` < `Thinking/Reasoning`
*   **架构档**：`Dense` < `MoE`
*   **输入档**：`Text-only` < `Multimodal`
*   **上下文档**：`短上下文` < `长上下文`
*   **部署档**：`闭源 API` < `开放权重/可私有化`

## 七、Dense 模型和 MoE 模型的区别

这是另一个底层关键概念。

*   **Dense Model**：每次推理都激活几乎全部参数。例如一个 700B dense 模型，每次生成 token 都要跑大量参数。能力强，但成本极高。
*   **MoE (Mixture of Experts)**：总参数很多，但每次只激活一部分专家。例如一个模型总参数 671B，但每个 token 只激活其中几十 B 的参数。这能让模型拥有巨大知识容量的同时，推理成本相对低。

> [!TIP]
> **通俗类比**：
> *   **Dense**：每个问题都让全公司所有人开会。
> *   **MoE**：由路由器 (Router) 先判断问题类型，只叫相关专家来处理。

## 八、上下文窗口不是记忆

很多人把长上下文 (Long Context) 和记忆 (Memory) 混为一谈，这是错的。

*   **上下文窗口**：是**这次请求**里模型能看到多少 token。例如 128k、1M tokens。
*   **记忆**：是**跨会话、跨任务**，长期保存并可检索的信息。

> [!TIP]
> *   上下文像你考试时**桌上的参考资料**。
> *   记忆像你脑子里**长期掌握的知识**。
> *   RAG 像你临时**去图书馆查阅图书**。

长上下文面临的底层挑战是 Attention 成本（传统 Attention 成本随长度平方增长）。常见问题包括：前后位置注意力不均、中间信息被忽略（Needle in a Haystack）、多个事实冲突时容易混、成本与延迟暴增。

所以在 Agent 产品里，不能因为模型支持 1M context 就把所有东西粗暴塞进去。正确做法是：**结构化记忆 + RAG + 摘要压缩 + 当前任务上下文**。

---

## 九、RAG 和模型本身的区别

*   **模型参数知识**：是训练时写进模型权重里的。
*   **RAG (检索增强生成)**：是推理时从外部知识库检索资料，再塞进 prompt。

比如你问：“我们公司上周的 PRD 是怎么写的？”模型参数里不可能有你公司的私有 PRD，必须用 RAG 检索并提供上下文。

RAG 流程一般是：
$$\text{用户问题} \rightarrow \text{Query改写} \rightarrow \text{向量/关键词检索} \rightarrow \text{Rerank} \rightarrow \text{取相关片段} \rightarrow \text{塞进 Prompt} \rightarrow \text{模型回答}$$

RAG 解决的是“知识新鲜度”和“私有知识”问题，不直接提升模型智商。**强模型 + 好 RAG**，才是企业知识问答的基本形态。

---

## 十、工具调用不是模型真的会操作世界

Function Calling / Tool Use 的本质是：**模型输出一个结构化 JSON，系统拿这个 JSON 去调用真实工具**。

比如模型输出：调用 `get_order(order_id=123)`。真正查数据库的是外部程序，不是模型本身。

模型在其中只负责三件事：
1. 判断该不该调工具；
2. 选择哪个工具；
3. 填对参数。

---

## 十一、Agent 不是一个模型，是一个系统

$$\text{Agent} = \text{LLM} + \text{工具} + \text{记忆} + \text{规划} + \text{执行循环} + \text{状态管理} + \text{权限控制} + \text{评估体系}$$

一个最简单的 Agent 循环是：
$$\text{用户目标} \rightarrow \text{模型规划} \rightarrow \text{调工具} \rightarrow \text{观察结果} \rightarrow \text{再规划} \rightarrow \text{再调工具} \rightarrow \text{输出结果}$$

Agentic Model 的意思不是“这个模型里面住了一个智能体”，而是**该模型更擅长在上述循环中工作**。

Claude 3.5 Sonnet 等顶级模型的竞争，已经从“单轮回答聪明”转向“长周期、多步骤任务的可信与可靠度”。

---

## 十二、多模态模型的底层原理

多模态模型不是“图片模型 + 文字模型简单拼接”。

一般做法是：
$$\text{图像} \rightarrow \text{Vision Encoder} \rightarrow \text{图像特征 token}$$
$$\text{音频} \rightarrow \text{Audio Encoder} \rightarrow \text{音频特征 token}$$
$$\text{文本} \rightarrow \text{Text Token}$$

然后统一送进大模型，让模型在**共同表示空间**里进行统一推理。图片在模型眼里不是 jpg，而是一串视觉 token。

---

## 十三、为什么不同模型“性格”不一样

模型性格主要来自**后训练 (Post-training)** 和 **产品包装 (Product Wrapper)**，而不是预训练：
*   **Claude**：谨慎、长文质量好、安全边界感强（因为 RLHF 偏好及安全策略不同）。
*   **GPT**：工具使用、复杂综合、代码和任务执行更均衡。
*   **Gemini**：多模态、Google 生态、长上下文场景突出。
*   **DeepSeek**：中文、代码、高性价比、开源生态支持度高。

---

## 十四、幻觉的底层原因

幻觉不是模型“故意骗人”。原因是：**模型的优化目标是生成高概率文本，而不是保证事实为真**。

解决幻觉在工程上需要靠：RAG、工具验证、引用来源、结构化输出、拒答机制、以及高风险场景下的规则过滤系统。

---

## 十五、为什么代码模型变强特别明显

代码比自然语言更适合训练推理模型，因为它具有天然优势：
1. 语法可验证；
2. 测试可运行；
3. 编译器/运行结果能给出直接反馈；
4. 单元测试能直接作为强化学习的 reward；
5. 错误修复有明确的闭环。

---

## 十六、为什么 Flash 这种快模型也能很强

Flash 类模型通过参数规模缩减、MoE 专家激活限制、从大模型中蒸馏、缩短推理路径等优化手段实现低延迟与低成本。

它适合 80% 的线上高频任务（分类、摘要、信息提取、客服路由、意图识别），但不适合复杂系统架构设计、长链路重构或深度数学证明。

---

## 十七、一个正确的模型认知框架

在评估任何模型时，不要粗暴地问“它是不是比 GPT 强”，应该拆成 **9 个工程问题**：

1. 它是 dense 还是 MoE？
2. 它是 base 还是 instruct？
3. 它有没有 reasoning mode？
4. 它的 reasoning tokens 是隐藏还是可见？
5. 它支持多长 context？
6. 它长上下文中间信息召回能力（Needle in a Haystack）怎么样？
7. 它是否支持工具调用和结构化输出？
8. 它是闭源 API 还是开放权重？
9. 它在我的特定业务评测集上成本、延迟、准确率、稳定性如何？

---

## 十八、把主流模型放到底层概念里

*   **GPT-5.5**：闭源顶级通用模型。属于高能力通用档，可根据任务分配不同计算强度的通用高阶模型。
*   **Gemini Pro**：高能力档，强调多模态和超长上下文。
*   **Gemini Flash**：速度/成本/吞吐档。
*   **Claude Sonnet**：平衡档，速度、成本、智能度极其均衡，适合作为主力生产开发模型。
*   **Claude Opus**：高能力档，偏复杂推理、长周期 Agent 和高自主性 coding。
*   **DeepSeek V 系**：通用模型代际，特点是 MoE、开放权重、中文和代码能力极强。
*   **DeepSeek R1**：典型推理模型 (Reasoning Model)，重点是通过强化学习强化思维链 (CoT) 推理过程。

---

## 十九、最关键的一句话

> [!IMPORTANT]
> **非推理模型是在已有模式里快速生成答案；推理模型是在生成答案前，用额外 token 和额外计算量构造一个临时推演过程。**

但两者底层都不是人脑。它们都是 Transformer 概率模型。
